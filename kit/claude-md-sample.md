# 🎁 この記事を丸ごと実装したCLAUDE.mdサンプル

チェックリストではなく、6つのThen→Nowルールを実際に書き込んだ「完成形」のCLAUDE.mdです。プログラミング初心者でも、自分のプロジェクト名・内容だけ書き換えればそのまま使えます。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: プロジェクトのルートに `CLAUDE.md` という名前で保存し、`< >` の部分だけ自分のプロジェクトに合わせて書き換えてください。

```text
# <プロジェクト名>

<このプロジェクトが何かを1〜2文で。例:「個人ブログの静的サイト。Next.jsで書いている」>

## 基本方針
- コードは周囲のコードに合わせて書く。コメントの密度・命名・書き方はその場の判断でよい。
- 頼まれていない機能追加・リファクタ・抽象化はしない。バグ修正には周辺の整理は要らない。
- 起こり得ない事態へのエラー処理・フォールバックは書かない。検証はユーザー入力や外部APIとの境界だけでよい。

## 進め方
- 十分な情報があれば手を止めずに進める。すでに合意した内容を蒸し返さない。
- 本当に必要な時（後戻りできない操作・仕様の解釈が分かれる時）だけ確認を求める。約束だけして終わらない。
- 作業の合間のメモは簡潔でよいが、最後の報告は結論から書く。矢印記号や省略記法は使わない。

## 検証・レビュー
詳しい手順はここに書かず `.claude/skills/verify/SKILL.md` を参照する。

## メモ・学び
このファイルへの手動追記は不要。関連する学びは自動でメモリに保存される。

## 参照
仕様の詳細は簡易メモではなく、`tests/` のテストコードと `mockups/*.html` を正とする。
```

**この書き方と、記事の6つのルールの対応**

| CLAUDE.mdの箇所 | 対応する転換 |
|---|---|
| 「コードは周囲のコードに合わせて」「その場の判断でよい」 | 転換①: ルール指定 → 判断委譲 |
| 「頼まれていない機能追加はしない」の一文だけで済ませている | 転換②: 例示 → インターフェース設計 |
| 検証手順を本文に書かず、別のSkillファイルを参照させている | 転換③: 全部前出し → 段階的開示 |
| 同じ注意点をあちこちに繰り返し書いていない | 転換④: 繰り返し → シンプルな説明 |
| 「手動追記は不要」と明記している | 転換⑤: 手動メモリ → 自動メモリ |
| 仕様の正を簡易メモではなくテストコード・HTMLに置いている | 転換⑥: 簡易仕様 → リッチな参照 |

**ポイント**: 完璧を目指さず、まずこのまま使い始めてください。使っていくうちに自分のプロジェクト特有の「落とし穴」（他の人が引っかかりやすい注意点）が見つかったら、その時だけ箇条書きを1つ足す——それくらいの軽さで十分です。
